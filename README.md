# 城市地下综合管廊运行维护管理平台

面向管廊主体台账、入廊管线登记、廊内环境监测、通风排水消防、结构沉降与渗漏处置、巡检检修与隐患整改、入廊作业审批和运维值班的一体化城市地下综合管廊运行维护管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `urban-utility-tunnel:entries` 这一项，或调用 `resetModule(模块)`。

## 门禁安防的写入与同步口径

门禁安防（`access`）不走通用动作按钮，页面全部读写收敛在
`frontend/src/api/access-domain.ts`，规则如下：

- **岗位授权**：出入口与安防责任岗位的归属登记在 `ENTRANCES`。提交检查、提出整改只接受
  本出入口责任岗位；其它岗位在该入口只读，越权提交直接驳回，驳回信息写明点位归属的
  出入口与责任岗位，记录归属与台账值都不变。顶栏可切换当前岗位用于验证。
- **一次落库、一处取值**：授权人数、门禁类型等字段随检查结论一次写入台账；列表、详情
  面板、另存 CSV 清单全部读同一份物理数据，不存在第二、第三种取值，刷新页面值不变。
- **同批材料幂等**：同一 `材料批次` 反复提交只算一次，版本号递增，仅最新版进台账，
  旧版标记 `superseded` 留痕，不与新版合并、也不会在续传时重放。
- **隐患与值班联动**：结论为「需整改」时按材料批次 upsert 一条隐患整改记录（落到
  `hazard` 清单）；检查结论同时写入**其它**出入口的值班交接清单（`duty`），两处文本
  由同一函数生成，内容严格一致，不写回本出入口；重报时原地刷新而不是新增重复行。
- **断线续传（outbox）**：同步通道断线时提交只进 `urban-utility-tunnel:access-state`
  队列、不动台账；恢复后按断点序号（seq）从第一条未同步记录续传，落库值取自该条自身
  携带的 payload，不用上一版值顶替。页面上可用「在线/断线」开关模拟。
- **存量迁移**：启动时只对上线前老台账（无责任岗位归属）按「检查日期」所在月份分批
  迁移（批次号 `MIGR-YYYYMM`），迁移幂等、只跑一次。历史取值对齐依据：
  - 授权人数：2025 年及更早按旧编制 6 人、2026 年上半年 12 人、2026-07 扩编后 16 人
    回填（依据门禁授权花名册历次扩编记录）；
  - 门禁类型缺失统一补「刷卡门禁」（存量设备普查底表）、监控覆盖缺失补「已覆盖」、
    检查人员缺失按岗位责任划分表补录；
  - 所有补齐项只补不抹，并在该记录「备注」里逐条写明出处与迁移批次。
- 自动化校验：`frontend/verify-access.mts`（经 `ts-node-loader.mjs` 以
  `node --experimental-loader ./ts-node-loader.mjs verify-access.mts` 运行）覆盖越权
  驳回、一次落库三处一致、刷新保持、同批幂等、断线续传与版本顶替、隐患/值班联动等场景。
