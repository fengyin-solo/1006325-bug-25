# 门禁安防写入与口径收口方案

针对「别的岗位替出入口提交照单收下、列表/详情/刷新/另存四个取值、整改不落隐患清单、反复提交重复计数、断线同步拿旧值顶」等问题，本次把门禁安防的写入路径与取值口径整体收口。纯前端版每个 localStorage 键对应后端一张表，切回后端时页面不用改。

## 1. 授权收口：提交检查、提出整改只认本出入口责任岗位

- 出入口与责任岗位的归属集中在 `src/data/access-domain.ts` 的《出入口授权名册》：
  每个出入口登记责任岗位（可多个）、班组、门禁类型、监控覆盖、标准授权人数。
- 所有写判断只在 `src/api/access-service.ts` 的 `submitAccessCheck` 里做，页面不做业务判断：
  - 岗位 + 出入口都匹配 → 允许提交；
  - 其它岗位（含值班管理员、其它出入口安防岗）→ 驳回，入口只读，并写明记录归属，例如：
    「提交被驳回：……不是东区1号口的安防责任岗位，该出入口对当前岗位只读。
    东区1号口归属东出口安防班组（责任岗位：东区安防一班、东区安防二班）。」
- 页面对无权限点位只给「详情」和只读标记；顶栏可切换值班身份用于演示。

## 2. 一次落库：授权人数、门禁类型只有一个正本

- 安防点位台账（`access` 行）是门禁类型、监控覆盖、授权人数的唯一正本。
- 首次提交检查结论时这些字段**定版一次**（缺值按名册补齐并在备注写明），之后列表、
  详情面板、CSV 另存清单（`exportEntries` 按同一份行导出）读到的完全一致；
  重新提交结论不再改动这些字段。
- 页面不缓存可变副本：每次操作后重取正本；跨标签页通过 `storage` 事件失效缓存，
  刷新、返回、重开浏览器读到的都是落库值。

## 3. 检查结论：同一检查只算一次，重报只留最新版

- 结论独立存于 `urban-utility-tunnel:access-checks`，主键 = `点位id@检查日期`。
- 反复提交执行 upsert：不新增记录、不并两版；版本号递增，保留首次提交时间与最近更新时间。
- 点位状态随最新结论更新（状态正常 / 需整改，终态 `pending=false`）。
- 提出整改时问题描述必填，否则驳回——结论必须能原样落进隐患整改清单。

## 4. 联动落库：整改进隐患清单，结论进值班交接清单

- **隐患整改清单（hazard）**：提出整改时按 `HAZA-ACCE-<点位编号>` upsert
  （部位、等级默认一般、措施=问题描述、责任人=责任岗位、期限=检查日+15 天、待整改）；
  复检正常则同一条验收关闭，不新增。同一点位永远只有一条对应隐患。
- **值班交接清单（duty）**：按 `DUTY-ACCE-<点位编号>-<日期>` upsert，交接事项文本由
  `handoverText()` 一个函数生成。门禁页面板与值班页面板读的是同一句，逐字一致。
- 隐患页、值班页订阅数据变更总线，另一处提交后自动刷新。

## 5. 同步队列：断线从断点续传，绝不拿旧值顶

- 队列持久化在 `urban-utility-tunnel:access-sync-queue`，每条只存 `任务类型 + 检查键`，
  **不存字段快照**；执行时回读最新结论再写台账（保证落的是最新版，不是入队时的旧值）。
- `drainSyncQueue()` 从队首逐条处理，任何一条失败立即停下，该条保留 `pending` 与失败原因；
  下次（恢复在线、点击续传、应用启动）从这一条继续。
- 同一检查重报：未完成的下发任务重置并回到等待，不新增、不合并两版。
- 门禁页同步条可切换在线/断线、手动续传、模拟「下一条同步中断」。

## 6. 存量迁移：按月份分批，缺项出处写进备注（v1）

`src/data/migrations.ts`，启动时按 schema 版本执行（幂等）：

- **分批**：以检查日期所在月份为批次，由前到后（种子存量为 2026-07 / 08 / 09 三批）；
  缺日期的归「月份不详」兜底批。
- **缺项补齐依据**：门禁类型、监控覆盖、授权人数按《出入口授权名册》；检查人员、
  安防责任岗位按名册归属；安防状态按当前检查状态。占位样例值（「门禁安防运维样例N」）
  与空值视为缺项。
- **可信现值沿用**：已有合法值（如 ACCE-0002 授权人数 18）不覆盖。
- **早年改过的记录（裁决）**：逐月历史过程值没有凭据，不予反推；保留迁移时点现值，
  备注注明「依据：上线前账面对接值（2026-10）」。本次对齐的是现值口径，不为历史编造版本。
- 每行备注逐项写明补齐项与出处，并打 `数据版本=1`；迁移日志（批次、逐行记录、告警）
  持久化在 `urban-utility-tunnel:migrations`，门禁页可展开查看。
